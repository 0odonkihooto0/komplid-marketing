22.08.2026 владелец прислал обновлённый прототип главной (Claude Design,
`145dd4a7-Komplid_Landing.dc.html`). Сверка с эталоном показала: содержательно
изменился **только первый экран** — герой и счётчики под ним. Остальные секции
прототипа от эталона не отличаются, разница лишь в том, что прототип шаблонный,
а эталон — раскрытая статика.

**Решения владельца:**

- H1 — «Вся стройка на одном столе.» вместо «Каждый акт — по СП…». Владельцу
  сказано, что образный заголовок слабее для SEO/AEO: ключевых слов в H1 не
  остаётся. Решение подтверждено.
- Счётчики под героем — про устройство контура: 5 этапов, 10 ролей, 8 сторон
  по ГрК, 344/пр. Прежние «323 свода правил / 22 калькулятора / 12 схем / 21
  модуль» с первого экрана ушли (остались в `PLATFORM_FACTS` для `SocialProof`).
- Регион сайта для Яндекс.Вебмастера — **Санкт-Петербург**. Тот же город теперь
  в `OrganizationSchema` и на `/company/contact`: панель, разметка и контакты
  должны совпадать, иначе регион не подтверждается.
- Объём работы — только первый экран. Не взяты (лежат в прототипе): боковая
  карточка вкладки «Мы компания» с приглашением команды, строка доплат у тарифов
  (хранилище пакетами, коннектор ИСУП), экран «Место закреплено за вами» после
  отправки формы.

**Два буллета героя изменены против прототипа** (CLAUDE.md §21): «323 СП и ГОСТ —
ссылка в акте» → «открыты без регистрации» (перехода на пункт норматива из акта
по коду приложения не подтверждено), «АОСР пачкой + XSD Минстроя» → «XML по
схемам Минстроя» (пакет формируем, подаёт его пользователь сам).

**Снимки интерфейса.** Правый столбец героя — два реальных экрана приложения:
`public/images/home/hero-phone.png` (мобильный, офлайн-очередь) и
`hero-web.png` (обзор договора «ЖК Северный, корпус 2»). Владелец показал их
картинками в чате, но файлами не приложил — кладёт сам. Пока файлов нет,
`readPublicImage()` (`src/lib/public-image.ts`) возвращает null и рисуется
заштрихованный плейсхолдер тех же пропорций: вёрстка проверяема без снимков,
а после появления PNG править нечего — размеры компонент берёт из самого файла.

**Грабли, на которые наступили при переносе:**

1. **Инлайновый `style` перебивает медиазапрос.** Дважды: подпись «мобильный»
   не пряталась на узком экране (`display: flex` инлайном), и снимок оставался
   обрезанным (`width: 1400` инлайном). Всё, что должен уметь менять брейкпоинт,
   держим классом или CSS-переменной (`--shot-w`), а не в атрибуте.
2. **Абсолютная обёртка съедает высоту.** Снимок лежит `position: absolute`
   внутри окна браузера, поэтому при `height: auto` на узком экране блок
   схлопывался в шапку. На брейкпоинте позиционирование возвращается в `static`.
3. **`metadata.icons` в layout вытесняет файловые иконки.** Стоило объявить там
   `apple`, как из `<head>` пропала автоссылка на `/icon.svg`. Apple-touch-icon
   заведён по файловому соглашению — `src/app/apple-icon.png`.
4. **`apple-icon.svg` Next игнорирует**: соглашение принимает только растр,
   лежавший в репозитории SVG отдавал 404 и ссылки на себя не имел. Генерация
   правильного PNG дописана в `scripts/make-brand-icons.mjs`.

**How to apply:** правя первый экран, начинать с `design/landing-reference.html`
(CLAUDE.md §2) и держать раскладку героя в `globals.css` — она размазана по
брейкпоинтам 1100 / 980 / 640, и инлайн в компоненте её ломает молча.
