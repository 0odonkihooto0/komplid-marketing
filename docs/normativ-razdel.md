# Раздел /normativ — база сводов правил (323 СП)

> Как устроен раздел, как его обновлять и что в нём нельзя трогать руками.
> Генератор страниц живёт в отдельном репозитории
> [mdTOhtmlBuild](https://github.com/0odonkihooto0/mdTOhtmlBuild) (локально `C:\HTMLartCopy`),
> правила работы с корпусом — в его `docs/03-CORPUS-PIPELINE.md`.

## Что это

323 свода правил в интерактивном виде: оглавление со scroll-spy, поиск по пунктам,
якорь на каждый пункт, таблицы, формулы и рисунки вырезками из оригинальных PDF.
Цель — SEO/AEO/GEO-трафик по запросам «СП 48 текст», «СП 20 нагрузки скачать»
и цитирование страниц AI-ассистентами.

## Устройство

| Что | Где | Чем создаётся |
|---|---|---|
| Страницы документов | `public/normativ/<slug>.html` (323 файла, самодостаточные: CSS и JS инлайном) | `sp-builder` в mdTOhtmlBuild |
| Картинки и вырезки формул | `public/normativ/img/<slug>/` (12 728 файлов) | там же |
| Реестр корпуса | `content/normativ/registry.json` | `tools/publish.py` |
| Хаб-каталог | `src/app/normativ/page.tsx` — 9 категорий, ItemList + Breadcrumb | код сайта |
| Чтение реестра, категоризация | `src/lib/normativ-data.ts` (+ тест) | код сайта |
| Чистые URL | `next.config.mjs`: rewrite `/normativ/:slug` → `:slug.html`, 301 с `.html` | код сайта |
| Записи в sitemap | `src/app/sitemap.ts` — хаб + 323 страницы | код сайта |

Страницы документов **не проходят через роутер Next** — это статика из `public/`,
отдаваемая по чистому URL через rewrite. Поэтому у них своя шапка и свои стили
(в дизайн-токенах Komplid), а не общий layout сайта. Ссылки в них ведут на
`/normativ/<slug>` и на komplid.ru — переезд на нативный рендер (этап 2 плана
`01-SP-PAGES-PLAN.md`) не сломает ни один внешний URL.

## Обновление корпуса

Всё делается в репозитории генератора, сайт только принимает результат:

```bash
cd C:\HTMLartCopy
python sp-builder/build.py --all -i normative-md -o sp-html      # пересборка (~100 с)
python tools/publish.py --dest C:\komplid_marketing\komplid-marketing
```

`publish.py` копирует изменившиеся HTML, зеркалит картинки (удаляя осиротевшие
только внутри `public/normativ/img/`), обновляет реестр и проверяет согласованность
(число страниц = числу опубликованных в реестре, canonical в каждом файле).

`npx next build` после этого нужен, **только если изменился состав корпуса** —
хаб и sitemap читают реестр на этапе сборки. Изменение содержимого страниц
подхватывается без пересборки сайта: `next start` отдаёт файлы из `public/` с диска
(перечитывая список файлов при старте — после добавления новых документов сервер
надо перезапустить).

## Правила

1. **`public/normativ/**` и `content/normativ/registry.json` — генерируемые артефакты.**
   Руками не править: любая правка потеряется при следующем `publish.py`. Источник
   правды — корпус в mdTOhtmlBuild.
2. **Слаги и якоря — публичный контракт**: `sp-48-13330-2019`, `#p-8-2-3`, `#pril-b`,
   `#tbl-2`. На них ссылаются извне, их цитируют AI-ассистенты. Менять — только
   с redirect-слоем.
3. **Не создавать роут `src/app/normativ/[slug]/`** — он перехватит адреса раньше
   rewrite, и статика перестанет отдаваться. Маска rewrite (`sp-[a-z0-9-]+`)
   намеренно не задевает хаб `/normativ` и `/normativ/img/...`.
4. **Ассеты коммитить отдельно от кода.** Раздел весит ~358 МБ; смешанный коммит
   невозможно ревьюить, а `git log` по коду становится бесполезен.
5. **Деплой дольше обычного** из-за объёма статики: первый push и первая сборка
   образа заметно тяжелее. Docker-образ включает `public/` и `content/` целиком
   (`.dockerignore` исключает `*.md`, наши `.html/.png/.jpg/.json` не задевает).
6. **Ссылки в навигации** («Нормативы» в шапке и мобильном меню, «База СП» в футере) —
   сначала правится `design/landing-reference.html`, потом компоненты. У `MobileNav.tsx`
   свой собственный список `NAV_LINKS` — его легко забыть.
7. **Жалоба на текст страницы** (битые символы, лишние строки) — это дефект корпуса,
   а не сайта. Чинится правилом в `sp-builder/cleanup.py` и пересборкой, править
   HTML на сайте бессмысленно.

## Проверка после обновления

```bash
npx tsc --noEmit && npm test          # код сайта
npx next build                        # если менялся состав корпуса
# на поднятом сервере:
curl -sI http://localhost:3200/normativ/sp-48-13330-2019      # 200
curl -sI http://localhost:3200/normativ/sp-48-13330-2019.html # 301 на чистый URL
curl -s  http://localhost:3200/sitemap.xml | grep -c normativ/ # 323
```
