Страницы СП — статика в `public/normativ/`, генерируется репозиторием
**mdTOhtmlBuild** (`C:\HTMLartCopy`). Здесь их не правят: любая правка потеряется
при следующей публикации. Устройство раздела — `docs/normativ-razdel.md`.

## Жалоба на текст страницы норматива

Это дефект корпуса, а не сайта. Идти в `C:\HTMLartCopy`, скилл `/fix-glyphs`:
правило в `sp-builder/cleanup.py` → тест → пересборка → публикация сюда.

## Обновление корпуса

```bash
cd C:\HTMLartCopy
python sp-builder/build.py --all -i normative-md -o sp-html   # если ещё не собрано
python tools/publish.py --dest C:\komplid_marketing\komplid-marketing
```

`publish.py` копирует изменившиеся HTML, зеркалит картинки, обновляет
`content/normativ/registry.json` и проверяет согласованность.

## Проверка

```bash
npx tsc --noEmit && npm test
npx next build          # только если изменился состав корпуса (хаб и sitemap читают реестр)
```

На поднятом сервере (`npx next start`, после добавления новых документов — перезапустить,
список файлов `public/` читается при старте):

- `/normativ` → 200, в каталоге все документы реестра;
- `/normativ/sp-48-13330-2019` → 200 (rewrite), `/normativ/sp-48-13330-2019.html` → 301;
- картинка `/normativ/img/sp-63-13330-2018/formula-1.png` → 200;
- `/sitemap.xml` содержит хаб и по записи на документ.

## Коммит

Код и ассеты — **разными коммитами**: раздел весит ~358 МБ, смешанный коммит
невозможно ревьюить. Деплой (`./deploy.sh`) запускает пользователь; после
обновления корпуса он дольше обычного.
