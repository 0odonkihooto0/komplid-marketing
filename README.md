# komplid-marketing

Правила работы над проектом — в [`CLAUDE.md`](CLAUDE.md), полный план — в

## Локальный запуск

Перед первым запуском нужен `.env.local` — без него `docker compose` не стартует
вовсе (файл указан в `env_file`, а в репозиторий он не коммитится):

```bash
cp .env.example .env.local
```

Значения можно оставить пустыми: сайт поднимется, отвалятся только аналитика
и пересылка лидов в приложение.

```bash
docker compose up          # http://localhost:3200, hot reload
docker compose down        # остановить
```

Без Docker — то же самое напрямую:

```bash
npm ci
npm run dev
```

## Если после `git pull` сайт выглядит не так

Контейнер хранит `node_modules` в томе, который переживает пересоздание
контейнера, а Turbopack — кэш сборки, который не замечает правок, сделанных
пока контейнер стоял. Оба случая выглядят одинаково: страница открывается,
но часть стилей или зависимостей старые.

`docker/dev-entrypoint.sh` разбирается с этим сам — сверяет `package-lock.json`
с содержимым тома и чистит кэш сборки при старте. Если что-то всё же осталось:

```bash
docker compose down -v && docker compose up --build
```

`-v` сносит том с зависимостями; без него `--build` пересоберёт образ, но том
останется прежним.

## Если сайт открывается, но не реагирует на клики

Не переключаются табы, тема, бургер, не отправляются формы — а страница выглядит
нормально. Это не дефект вёрстки: в dev-режиме Next.js **не гидратирует страницу,
пока не установится HMR-вебсокет**. React не монтируется, обработчиков нет.

Признак в консоли браузера — `WebSocket connection to 'ws://localhost:3200/...'
failed`. Признак в логе контейнера — после `GET /` не появляется
`GET /api/waitlist-seats` (его шлёт счётчик мест уже из браузера).

Что делать по порядку:

1. Открыть **`http://127.0.0.1:3200`** вместо `http://localhost:3200`. На Windows
   `localhost` резолвится в IPv6 `::1`, а порт Docker слушает IPv4: HTTP
   откатывается на IPv4 сам, вебсокет — часто нет.
2. Проверить брандмауэр и антивирус — веб-защита умеет резать WebSocket
   на локальных портах.
3. Системный прокси: добавить `localhost;127.0.0.1` в исключения.

Если вебсокет так и не поднялся, посмотреть сайт можно в прод-режиме — там
HMR-клиента нет вовсе:

```bash
docker compose -f docker-compose.preview.yml up --build   # http://localhost:3200
```

Горячей перезагрузки в нём нет: после правок нужен повторный `--build`.
Подробности — `docs/memory/dev-hmr-websocket-hydration.md`.
